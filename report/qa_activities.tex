\section{Test Plan}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Scope}

This plan covers functional testing of the GreenStep Employee web application:
authentication and route protection, onboarding, action logging (including
note/photo bonus points and the duplicate-submission guard), streaks, the
team-request and admin-approval workflow, leaderboards (team and individual,
with tie handling and category/time filters), administrative tools (challenge
creation, join-by-code, CSV export, admin-only access), and the error/404
pages. Performance, load, and security penetration testing are out of scope
for this phase.

\subsection{Test Environment}

\begin{itemize}
    \item \textbf{Application:} Next.js~15 build, run both locally
    (\texttt{npm run dev} at \texttt{localhost:3000}) and on the deployed
    Vercel instance.
    \item \textbf{Browsers:} Desktop Chrome and mobile-width viewport (the UI
    is mobile-first).
    \item \textbf{Auth:} Clerk test instance; an admin account with
    \texttt{publicMetadata.role = "admin"} and one or more standard accounts.
    \item \textbf{Database:} Neon PostgreSQL (development branch), inspected
    with Prisma Studio (\texttt{npm run db:studio}); seed scripts under
    \texttt{scripts/} provide demo data.
\end{itemize}

\subsection{Approach and Responsibilities}

Testing was \textbf{manual}, exploratory plus the scripted cases in
Table~\ref{tab:tc}, executed against two or more accounts to exercise
multi-user flows (teams, leaderboards). Hadi led test execution and the final
end-to-end pass; each team member tested the features they implemented, and
defects were recorded as GitHub issues and fixed on feature branches. Pass/Fail
reflects the current build; fixed defects are listed in
Table~\ref{tab:defects} with their commit references.

\section{Known Limitations}
% ─────────────────────────────────────────────────────────────────────────────

Defects \texttt{D-11}--\texttt{D-13} above are the project's known limitations,
recorded as open defects for transparency: there is no edit/undo of a logged
action; action data is self-reported on an honor-system basis with no
verification; and the main dashboard component remains large and is slated for
decomposition into per-tab components. These are also reflected in the
To-Do / Future Enhancements section of the Project Report.
